# KTU Pulse — Delivery Criteria

- [ ] **Foundation, visual system, and safety:** Implement a strict TypeScript Next.js App Router project using Tailwind CSS, Lucide icons, next-intl, local typed data, and route handlers. Use warm ivory `#F8F7F2`, deep teal `#174C45`, sage `#DCE8D8`, sparing coral `#E98C70`, readable dark text and borders, Space Grotesk/Inter fallbacks, crisp borders, modest corners, intentional hard shadows, focus rings, reduced motion, and no neon/glassmorphism/giant hero/generic purple dashboard patterns. Do not expose credentials, private student information, fictional official records, or KTU login simulation.

- [ ] **Shared responsive navigation and accessibility:** Build desktop and mobile layouts with KTU Pulse wordmark; Home, Examinations, Results; global search; language selector; unread notification indicator; compact settings/profile controls; active-page indication; mobile menu/drawer or bottom navigation containing Home, Exams, Results, Ask Pulse/Help. Provide semantic headings, descriptive labels and helper text, keyboard-operable menus/dialogs, screen-reader labels, visible focus, touch-friendly controls, logical tab order, meaningful loading/error/empty states, optional text size and optional browser read-aloud with accurate support disclosure. Ensure 320px, 375px, 430px, tablet, laptop, and desktop layouts have no horizontal overflow, clipped navigation, tiny controls, hover-only essentials, or obstructive sticky elements.

- [ ] **Home and Pulse Priority:** Create a concise student dashboard with welcome text, global search, Exams/Results quick links, and a compact interactive Pulse Priority with Action required, Coming up, and New updates categories. Show only supported fields, clear required-action labels/source links and deadlines only when present. Mark every fictional record visibly as DEMO DATA and never imply dates/notices are official. Add functional quick access, upcoming sample examinations, searchable/category-filterable latest announcements with title/category/date/summary/source, and compact Ask Pulse help prompts.

- [ ] **Examinations discovery:** Create an Examinations page with title/explanation/search and functional keyword, academic year, examination type, supported programme/semester filters, reset filters, visible active state, matching count, responsive cards/table, and sample labels. Display only supplied name/year/type/date/status/source fields. Provide distinct loading, available results, no matching records with clear-filters guidance, not-configured, and retryable network/server error states; do not use “No records found” for every failure.

- [ ] **Results demo workflow:** Build an understandable public no-credential results interface with a semester selector, validation/helper text, View Result action, loading state, selected-semester updates, and a polished print-friendly fictional grade card labelled DEMONSTRATION DATA. Include Demo Student, fictional ID, programme, semester, academic year, subject codes/names, credits, grades, result status, and only supported SGPA with simplified calculation explained. Provide a working print action; do not offer download PDF unless a real implementation exists.

- [ ] **English and Malayalam internationalisation:** Implement complete English and Malayalam dictionaries for all visible navigation, headings, buttons, labels, filters, validation, empty/error states, notification categories/preferences, accessibility settings, chatbot UI and suggestions, helper text, and confirmations. Support `/en`, `/en/exams`, `/en/results`, `/ml`, `/ml/exams`, and `/ml/results`; switch the current page while retaining useful filters/query state, persist preference, show active language, handle Malayalam Unicode, and set correct language metadata. Do not present translated summaries as official source content.

- [ ] **Global search, Ask Pulse, and notifications:** Make global search work across local notices, exams, and resources with grouped matching suggestions, count, keyboard navigation, reset, no-results state, relevance emphasis where practical, and page/source navigation. Build site-wide Ask Pulse with floating trigger, expandable accessible panel, welcome, suggestions, history, user/assistant styles, local contextual responses, typing/loading, error/retry, clear action, input/send, source/internal links, and no invented academic facts or requests for passwords/OTPs. Implement a notification centre with unread count, categories/dates, read/unread state, mark-one/mark-all, relevant links, and preferences for Examinations, Results, Deadlines, General announcements. Do not claim live push delivery; reserve safe integration points.

- [ ] **Data/API integration seams and verification:** Keep notices, examinations, sample results, and notifications in typed separate data modules with clear sample labels. Add safe `GET /api/notices`, `GET /api/examinations`, `POST /api/chat`, `GET/PUT /api/preferences`, `GET /api/notifications`, `PATCH /api/notifications/[id]/read`, `POST /api/push/subscribe`, and `POST /api/push/unsubscribe` route points without inventing KTU APIs or a public results endpoint. Create route manifest, validate key interactions and route rendering, run diagnostics, lint/type checks and production build, repair errors, and summarize which features are demo-only and which require authorized production integrations.
